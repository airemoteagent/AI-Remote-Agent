# IEC 62443-4-2 — Technical Component Security Requirements Mapping

> **Status:** evidence-based alignment · **Standard:** IEC 62443-4-2:2019 —
> Security for industrial automation and control systems — Part 4-2: Technical
> security requirements for IACS components.
>
> The remote-agent daemon is treated as an **embedded/software component (SL-2
> target candidate)** when deployed in an industrial workflow. This document maps
> the 7 **foundational requirements (FR 1–7)** and the relevant **component
> requirements (CRs)** to implemented controls and tests. Items marked **N/A** are
> not applicable to a software daemon (e.g. physical tamper resistance, emergency
> power) and are stated as such rather than claimed.
>
> Companion process document: `docs/IEC-62443-4-1.md` (secure development lifecycle).

---

## 0. Component model

- **Host:** unprivileged user process (no elevation required) on macOS/Linux/Windows.
- **Interfaces:** outbound HTTPS only (task polling every ~2 s + metrics every ~10 s);
  **no listening sockets** (localhost metrics port is opt-in and loopback-bound).
- **Credentials:** one revocable device token, stored 0600; Ed25519 device identity
  for enrollment (`packages/engine/src/device-registry.js`).
- **Trust assumption:** the local `~/.remote-agent/policy.json` is authoritative;
  the control plane can never widen it.

| CR 1.12 | System use notification | Local audit log records every policy decision | Implemented |
| CR 1.13 | Access via untrusted networks | TLS 1.2+ with certificate verification; no insecure fallback | Implemented |

## 8. Security-level rationale

remote-agent targets **SL-2** for its *software* CRs: it defends against
deliberate violation using simple means with low resources and generic skills,
which matches an unprivileged, egress-only, policy-gated daemon. A formal SL
claim requires an accredited component assessment; this document is the input
to that assessment, not the certificate.

**Not applicable / not claimed:** physical tamper resistance (CR 3.11), boot
integrity (CR 3.14), emergency power (CR 7.5), wireless (CR 1.6/2.2), portable
device use control (CR 2.3) — the daemon is a software component with no
physical attack surface of its own.
