head · who governs this device

The head is remoteagent.online: it holds the roster and the API key. linked means a key is present on this device — nothing is claimed without one. roster is what the head can see, runtimes how many agent runtimes answered.

runtime coverage · what answered

One row per runtime adapter. read is how long that runtime's own store needed; a note here is the honest reason a runtime shows nothing. Adapters run in a child process, so a slow store cannot freeze this page.

where the cpu goes

agents = detected agent processes, control = the surfaces watching them, system = the OS.

sessions right now · all runtimes

Newest first, straight from each runtime's store. running = it wrote within the last 90 s. Click any row to expand the session: objective, todos, files touched, last steps and its source path.

agents · every known agent, running or not

Three detection tiers, shown in the "why" column: signature (known agent executable — claude-code, aider, codex, goose, mcp-server, …), registry (your own entry in ~/.remote-agent/agents.json) and possible (agent-ish runtime — displayed, never asserted). A shell that merely mentions an agent is not one. Every action passes the policy gate; a refusal is printed.

sessions · every agent session on this device

Each runtime keeps its own store (transcripts, sqlite, json index). This merges them: who (runtime), what (task), how far (todos), where (cwd), when. Click a row to expand it.

activity · what the agents are actually doing

Two feeds in one table: the audit chain 🔒 (every governed action on this device, hash-chained) and the step feed of every runtime (think 🧠 / read 👁 / edit ✏️ / run ▶ / say 💬), read from the runtimes' own transcripts.

devices · governed, and probed rather than assumed

A peer in ~/.remote-agent/fleet.json is a claim until its control port answers — probe shows the reason (tcp host:port ok / ECONNREFUSED). A self device can pause/resume its own agents; peers are probe-only because no remote control channel exists, and the button says so instead of pretending.

security · what is enforced, and what was refused

Policy is read from local disk only — a remote update is rejected. The audit log is append-only and hash-chained: chain ok proves no line was rewritten, broken @N names the first line that does not verify. The kill switches are policy-gated too.
